# Core Beliefs

Operating principles for Let's Farty, adapted from the supplied harness template.

1. Keep repository knowledge beside the code, with one owner for each rule and links from agent entry points.
2. Prefer executable, fixture-tested checks for structural rules; keep approval, semantic correctness, and quality judgments human-reviewed.
3. Make guidance useful to both people and coding agents: start at [AGENTS.md](../AGENTS.md), then [ARCHITECTURE.md](../ARCHITECTURE.md), then focused references and source.
4. Derive generated documents from a real source; do not hand-maintain duplicate descriptions.
5. Create product packages with their consuming feature, keeping proposed layouts distinct from implemented components.
6. Preserve the [MVP's](design/active/2026-10-14-lets-farty-mvp-design.md) privacy, consent, and evidence boundaries. A fun acoustic score is not a health assessment.
7. Record failures and unavailable checks honestly; fixtures, metadata, and advisory scans never establish production readiness by themselves.
